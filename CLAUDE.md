# vestaboard-channels

Posts content to a Vestaboard Flagship split-flap display via the Read/Write
API. The scheduler and channels run as a Cloudflare Worker (`worker/`,
TypeScript). Python versions of the channels (`channels/`, `vestaboard/`)
remain as the manual fallback and the parity reference for the port.

## Board facts

- 6 rows × 22 columns. Character codes: 0 = blank, 1–26 = A–Z, 27–36 = 1–0,
  punctuation up to 62, colored tiles 63–71. Full table in
  `worker/src/board/characters.ts` / `vestaboard/characters.py`
  (source: docs.vestaboard.com/docs/characterCodes).
- API: POST/GET https://cloud.vestaboard.com/ with `X-Vestaboard-Token`.
  Rate limit: one message per 15 seconds (the Worker client waits once on
  429). Blank messages are rejected. 423 = board muted (quiet hours).

## Conventions

- **The Worker is the clock.** `worker/src/schedule.ts` lists every post in
  Pacific wall-clock time; the cron fires every minute and `slotAt` decides.
  Never add GitHub `schedule:` triggers: GitHub fired them 4–8 hours late.
- One channel = one module in `worker/src/channels/` exporting a `Channel`
  (`render(ctx, opts)` returns pages; it must never post). Posting happens
  only in `worker/src/index.ts` (scheduled handler, or `POST /run` with the
  admin token). `GET /preview/<channel>` is the dry run.
- Data files (`menu.json`, `holidays-data.json`, `letter-words.json`) are
  bundled at deploy time; edit + push to `main` redeploys.
- Keep the Worker dependency-free at runtime (fetch + Intl only). Python
  side: `requests` only.
- Tests: `cd worker && npm test`. `test/fixtures/parity.json` holds grids
  generated by the Python channels (`python worker/test/gen_parity.py` from
  the repo root); the TypeScript output must match cell for cell. If you
  change a Python channel, regenerate; if you change layout in TypeScript
  only, change the Python too or drop that case from the generator.
- Never post during development. Local dev: `npm run dev`, then
  `curl localhost:8787/preview/<channel>`.
- Python fallback: `python -m channels.<name> --dry-run` (`--date YYYY-MM-DD`
  where supported); workflows are `workflow_dispatch` only.
